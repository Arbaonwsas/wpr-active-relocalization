# 重定位算法与参数


导航启动后，调用以下服务可执行完整的主动全局重定位：

```
ros2 service call /global_relocalization std_srvs/srv/Trigger "{}"
```

该过程会取消正在执行的导航目标、停止底盘、重新全局散布 AMCL
粒子并原地旋转扫描。若旋转后仍存在对称定位假设，系统会依据实时激光
净空选择安全方向短距离平移，再反向扫描。只有多个不同 AMCL 更新的
协方差和激光—地图一致性评分连续通过阈值时才返回成功；失败时机器人
会停车，不会在错误定位上继续导航。

恢复运动每个控制周期都会检查激光和里程计的接收时间，任一数据超过
`sensor_timeout`（默认 `0.5 s`）未更新即发送停车命令并终止本次恢复。
平移净空按半径 `0.22 m` 的圆形底盘扫掠路径计算，保留单束近障碍物，
不再使用会忽略窄障碍物的距离分位数；更换底盘时需同步调整
`translation_robot_radius` 与 Nav2 代价地图的机器人尺寸。

恢复前必须成功取消 `navigate_to_pose` 和 `navigate_through_poses` 导航，
并等本次取消涉及的动作进入终止状态。取消服务不可用、拒绝或终止等待
超时均报告失败，不开始恢复运动。恢复运动中若观测到新的活动导航目标，
也会停车并终止恢复；这属于状态监控保护，并不替代独立的速度仲裁器。

导航配置默认同时启用两级自动质量看门狗。当前位姿的激光—地图匹配分数低于
`0.35`、有效激光端点大量落出地图，或 AMCL 协方差超过成功门槛时，必须连续
12 帧（20 Hz 激光下约 `0.6 s`）才会自动调用同一套全局重定位。对于协方差很小
但定位错误的情况，第二级看门狗检查 40 帧滑动窗口；窗口内至少 90% 的分数低于
`0.60` 时触发（约 `2 s`），少量偶发好帧不会清空历史。恢复期间不会重复触发，
完成后还有 `8 s` 冷却时间；上述手动服务始终保留。

本仿真的平面运动插件会在 Gazebo 拖动模型时同步改变 `/odom`。看门狗还会检测
相邻里程计样本超过 `0.75 m` 或 `0.80 rad` 的不可能突跳，因此即使机器人在重复
场景中形成分数较高的错误定位，也能可靠触发连续拖动实验。真实机器人没有这个
仿真特征，仍由前述两级激光—地图质量规则检测绑架问题。

同一仿真特征也用于防止镜像位置误报成功：`simulation_odom_validation` 默认在本
课程仿真配置中启用，要求 AMCL 与仿真里程计的位置误差不超过 `0.75 m`、航向误差
不超过 `0.60 rad`。该条件是 Gazebo 测试预言机，不应在真实机器人配置中启用，
也不能作为严格“里程计不知情”的绑架实验结果。

若一次自动恢复完成全部尝试后仍失败，看门狗会锁存失败并停止周期性重试，避免
机器人在不可观测的对称位置无限旋转。定位自行恢复正常或下一次 Gazebo 拖动产生
新的里程计突跳时，锁存自动解除；手动 `/global_relocalization` 服务不受影响。

连续体验自动恢复时，只需在 Gazebo 暂停物理、将 `wpb_home` 移到没有碰撞的
新位置并恢复物理，不要调用服务，也不要在 RViz 点击 `2D Pose Estimate`。正常
情况下约 0.6 秒后机器人会自动开始旋转扫描，恢复成功并静止后可以再次暂停、
移动和恢复。

可用下面两个话题监控过程：

```
ros2 topic echo /global_relocalization/status
ros2 topic echo /global_relocalization/quality
```

注意：本仿真模型使用 `libgazebo_ros_planar_move.so`，在 Gazebo 中直接拖动模型
会使 `/odom` 同时跳变，适合连续功能体验，但不属于严格的里程计不知情绑架测试。
正式基准仍以 Gazebo 真值、AMCL 误差和分阶段时间作为判据。

### 实验模式：多候选与主动消歧

`active_hypothesis_relocalization` 默认关闭。开启时，恢复流程改为：

1. 从已知栅格地图和当前激光进行粗到细全图匹配，保留最多 8 个相互分离的位姿候选。
2. 比较候选的当前分数和连续观测平均分数；至少两个新扫描都能以足够差距区分候选，
   才将激光计算得到的位姿发布到 `/initialpose`，交由 AMCL 静止复核。
3. 有歧义时，预测候选在多个相对方向移动后的扫描差异，优先选择相较原地能增加
   区分度的动作。只选择实时激光净空足够、
   且所有主要候选在地图中都可安全通过的动作。每步最多 0.9 m，最多 3 步，
   累计平移预算默认 1.8 m。每步后以相对里程计推进候选，并用新扫描重新评分。
4. 没有安全且有区分度的动作、预算耗尽或 AMCL 偏离候选时，返回失败并停车，
   不回退到可能误报成功的单假设验收。

试验参数（在停止已有重定位节点后运行，避免重复速度发布）：

```bash
ros2 run wpr_simulation2 active_global_relocalization.py --ros-args \
  --params-file "$(ros2 pkg prefix --share wpr_simulation2)/config/nav2_params.yaml" \
  -p active_hypothesis_relocalization:=true \
  -p simulation_odom_validation:=false \
  -p automatic_relocalization:=false
```

候选生成与动作选择不读取 Gazebo 真值、AMCL 先验或绝对里程计位置；只在移动后使用
相对里程计增量。`/initialpose` 的内容来自激光全图匹配，而非人工给出答案。
使用 `simulation_odom_validation:=false` 可以关闭原有仿真真值验收，
但 Gazebo 原插件的 `/odom` 和 TF 仍会随拖动跳变。严格的全链路绑架实验还需要
隔离插件的真值 TF，不能仅凭关闭这个参数就宣称完成严格实验。

该模式需要 NumPy。目前针对本项目的水平栅格地图实现，尚未完成大地图、动态人群、
低重叠扫描和广泛随机位置验证。完全相同且可达区域也对称的地图仍会保持歧义；
候选分数差只是一种工程判据，并非正确定位的数学保证。

### 全局重定位基准测试

2026-08-03 的首轮三位置基准测试全部恢复成功，平均墙钟恢复时长为
186.49 秒。详细时长、真实位姿误差、原始状态日志和复测方法见
[基准测试记录](../benchmark_results/2026-08-03_baseline/README.md)。

需要进行重复计时实验时，可在导航和 Gazebo 已启动后执行：

```
python3 scripts/benchmark_global_relocalization.py \
  --repetitions 10 \
  --output-dir benchmark_results/relocalization_repeat_10
```

可重复使用 `--location top_left_room`、`--location map_center` 或
`--location bottom_right_area` 只选择部分位置。每次运行会生成：

- `results.csv`：每次实验的总时间、各阶段累计时间、误差和成功状态；
- `phase_timings.csv`：每次尝试中初始化、扫描、确认、平移、停车和清图的
  起止墙钟/仿真时间；
- `README.md`：分位置成功率、P50、P95、最大恢复时间、阶段耗时占比和实验
夹具开销；
- `status_*.log`：带 `run_id` 和事件序号的原始状态事件，避免混入上一次
  瞬态持久消息。

算法阶段时间和暂停、传送、恢复 Gazebo、采集结果等实验夹具时间分开统计，
因此后续优化时不会把测试脚本本身的等待误认为重定位耗时。

当前正式 10 Hz 三位置三十次测试成功率为 `30/30`，平均服务墙钟时间 `4.94 s`、
P50 `4.36 s`、P95 `7.73 s`。停车后新增两次 AMCL 静止质量复核；仿真激光提高到
20 Hz 后，三位置九次初步对照仍为 `9/9`，节点内部平均恢复由 `4.68 s` 降至
`3.65 s`。完整参数 A/B、硬件利用率和下一阶段方向见
[重定位时间优化记录](relocalization_time_optimization.md)。
